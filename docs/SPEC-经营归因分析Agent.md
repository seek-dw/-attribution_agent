## 1. 目的与读者

本文档定义系统的**对外可观察行为**：什么输入、什么输出、什么状态下拒绝、拒绝时给出什么依据。

本文档不规定技术选型、框架、表结构、目录组织、部署方式。这些属于实现方案。实现与本文档冲突时以本文档为准。

### 1.1 限定词

| 词 | 含义 |
| --- | --- |
| **必须** | 绝对要求，不满足即缺陷 |
| **不得** | 绝对禁止，出现即缺陷 |
| **应当** | 强建议，偏离须书面说明理由 |
| **可以** | 可选 |

需求编号 `FR-*` / `NFR-*` / `AC-*` 一经分配不复用、不改义。

## 2. 项目定位（区别于已有项目，供答辩使用）

系统要回答的不是"数字是多少"，而是"**为什么**，凭什么这么判断，还缺什么才能确定"。

### 2.1 与已有项目的边界

| 维度 | 问数项目 | 舆情分析 | 本项目 |
| --- | --- | --- | --- |
| 输入 | 一个明确取数问题 | 一个主题 | 一个**模糊的因果疑问** |
| 交互 | 单轮 | 单轮采集 | **多轮追问与补充证据** |
| 工具调用 | 一条 SQL | 并行多源采集 | **按假设需要动态选择查询/文件/检索/命令** |
| 输出 | 一个结果集 | 汇总报告 | **结论 + 逐条证据 + 缺口 + 下一步建议** |
| 失败语义 | 查不到即无数据 | 采不到即缺失 | **缺证据必须显式声明，不得用推理补** |

### 2.2 核心能力主张

**假设-取证-收敛循环**：把模糊问题拆成可验证的子假设 → 为每个假设选择取证手段 → 执行取证 → 判定该假设成立/不成立/证据不足 → 收敛到结论或向用户索要缺失数据。

这个循环是本项目的全部价值所在。**若实现退化为"一次取数 + 一段总结"，本项目不成立。**

## 3. 术语（规范性）

| 术语 | 定义 |
| --- | --- |
| **分析任务** | 一条用户消息触发的一次完整分析执行。有独立 ID 与生命周期 |
| **分析轮** | 一次分析任务内的一个推理周期：识别问题 → 规划 → 取证 → 判定 |
| **假设** | 一个待验证的因果或差异命题，如"某类目销量下滑导致总销售额下降"。必须有可判定的成立条件 |
| **证据** | 支撑或否定假设的一条可核验事实。必须含来源、取数方式、口径、时间范围 |
| **口径** | 指标的计算定义：分子、分母、过滤条件、统计周期 |
| **证据缺口** | 当前假设无法判定所缺的具体数据项。必须具体到可索取的程度 |
| **阶段性结论** | 一轮分析后的中间判断，允许被后续证据推翻，必须记录推翻原因 |
| **上下文摘要** | 对历史消息的压缩记录，用于长会话。必须保留可追溯的原始消息区间 |
| **工具** | Agent 可调用的能力：数据库查询、文件读写、文本检索、命令执行、结果文件生成 |
| **执行边界** | 一次分析任务被允许触达的资源范围与时限 |
| **可核验** | 给定证据记录，第三方能凭其中的来源与口径复现同一数值 |

## 5. 功能需求

### 5.1 认证与登录（S1）

**FR-1.1** 系统必须提供授权登录入口页，展示登录动作，不展示业务数据。

**FR-1.2** 必须提供登录回调处理：接收回调参数 → 换取访问令牌 → 建立登录态 → 跳转工作台。

**FR-1.3** 登录态校验失败时，访问任意业务页必须被拒绝并跳回登录入口，**不得**返回空白页或部分数据。

**FR-1.4** 系统必须区分"分析用户"与"系统管理员"两类角色。管理员专属能力不得对分析用户开放。

**FR-1.5** 所有业务接口必须做登录态校验。**不得**存在无鉴权的业务数据接口。

### 5.2 会话与消息（S2）

**FR-2.1** 会话状态必须至少包含 `active`、`archived`、`deleted`。`deleted` 后**不得**出现在列表查询中。

**FR-2.2** 分析任务状态必须至少包含 `queued`、`running`、`success`、`failed`、`cancelled`。状态迁移必须单向，**不得**回退。

**FR-2.3** 一条用户消息必须对应且仅对应一次分析任务。

**FR-2.4** 同一会话同一时间**不得**存在多个 `running` 状态的分析任务。并发发送第二条消息时，必须拒绝或排队，且拒绝/排队行为必须一致可预期。

**FR-2.5** 删除会话时，必须同时删除该会话下的消息、附件记录、任务记录、结果记录、上下文摘要记录，以及 §5.10 规定的对应目录。**不得**残留孤儿数据。

**FR-2.6** 消息必须有单调递增的顺序号，历史消息回放必须按顺序号返回，**不得**出现乱序或重复。

**FR-2.7** 系统必须支持会话新建、重命名、删除、切换、历史消息查询。

### 5.3 附件（S3）

**FR-3.1** 必须支持当前会话下的附件上传、删除、下载。

**FR-3.2** 附件列表必须至少展示：文件名、文件类型、文件大小、上传时间、解析状态。

**FR-3.3** 上传后必须产生解析动作，解析状态必须可观测，至少区分：待解析、解析中、成功、失败。失败必须记录可读原因。

**FR-3.4** 附件路径必须经校验，**不得**通过构造路径读取执行边界之外的文件。

**FR-3.5** 下载必须校验附件归属于当前用户与当前会话。

**FR-3.6** 附件解析结果必须可被分析任务作为证据来源使用，并在证据中标注来源为该附件。

### 5.4 实时任务通道（S4）

**FR-4.1** 分析任务必须通过长连接实时返回中间消息与最终结果。**不得**仅在任务结束后一次性返回。

**FR-4.2** 长连接必须鉴权。**不得**允许未认证连接订阅任意会话。

**FR-4.3** 长连接凭据必须短时有效且一次性使用，重复使用必须被拒绝。

**FR-4.4** 必须支持以下消息类型，字段满足原文 2.1.10：

| 类型 | 最小字段 |
| --- | --- |
| `message_start` | task_id, conversation_id |
| `message_delta` | task_id, delta_text |
| `tool_start` | task_id, tool_name |
| `tool_finish` | task_id, tool_name, tool_result_summary |
| `task_status` | task_id, task_status, current_step |
| `result_ready` | task_id, result_id |
| `error` | task_id, error_message |
| `done` | task_id, finished_at |

**FR-4.5** 连接中断后重连，必须能获取当前任务状态，**不得**因断连导致任务丢失。

**FR-4.6** 取消分析必须先停止后续步骤执行，再更新状态为 `cancelled`。已完成步骤的记录必须保留。

### 5.5 分析执行与工具（S5）

**FR-5.1** 系统必须实现"假设-取证-收敛"循环：把用户问题拆成可判定的假设，为每个假设取证，判定成立/不成立/证据不足，收敛到结论。

**FR-5.2** 系统必须支持以下五类工具，且每次调用都必须产生 `tool_start` / `tool_finish` 事件：

| 工具 | 能力约束 |
| --- | --- |
| 数据库查询 | **只读**。禁止 INSERT/UPDATE/DELETE/DDL。必须有返回行数与耗时上限 |
| 文件读取 | 限于执行边界内的路径。必须有单文件大小上限 |
| 文件写入 | 限于 `workspace/{user_id}/{conversation_id}/`。越界拒绝并记日志 |
| 文本检索 | 限于已上传附件与已生成结果。必须返回可定位的片段 |
| 命令执行 | 白名单命令集；工作目录限于 workspace；必须有超时与输出长度上限 |

**FR-5.3** 数据库查询工具必须在执行前做语句校验。非只读语句必须被拒绝，并记录事件。**不得**依赖数据库权限作为唯一防线。

**FR-5.4** 命令执行必须限定白名单。非白名单命令必须被拒绝。必须设置超时；超时必须终止进程并记录。输出必须截断到上限并标注已截断。

**FR-5.5** 文件读写必须限定在执行边界内。路径穿越（`..`、符号链接、绝对路径逃逸）必须被拒绝。

**FR-5.6** 当问题缺少必要信息（分析对象、时间范围、指标口径、对比基准）时，系统必须提出澄清并等待回答，**不得**以默认值静默填充后继续分析。

**FR-5.7** 澄清中断后，系统必须能从断点恢复，**不得**要求用户重复提供已给出的信息。

**FR-5.8** 工具执行失败时，系统必须记录失败原因，并在后续推理中将其视为"证据不足"，**不得**将失败静默当作"无异常"。

**FR-5.9** 单次分析任务必须有步骤数与总时长上限。超限必须终止任务并给出可读原因。

**FR-5.10** 当某项证据不足以支撑结论时，系统必须把该数据项列入"待补充数据"，**不得**用推理或常识补全后作为结论输出。

**FR-5.11（防退化）** 对形如"为什么 X 发生了"的因果类问题，单次分析任务**必须**：

1. 产出**至少 2 个**可判定的假设，每个假设写明判定条件；
2. 对每个假设独立取证并给出判定（成立 / 不成立 / 证据不足）；
3. 在结果中**显式列出**被否定的假设及其否定依据。

若某次分析确实只存在单一假设，系统必须说明为何无法拆出第二个假设，**不得**静默跳过。

> 本条存在的理由：本系统若退化为"执行一次查询 + 生成一段总结"，则与单轮问数项目无异，项目不成立。本条是该退化的唯一自动化防线，对应 AC-19。

### 5.6 结构化结果（S6）

**FR-6.1** 每次成功的分析任务必须产出结构化的六部分结果，字段满足原文 2.1.11：

| 部分 | 要求 |
| --- | --- |
| 问题定义 | 当前分析要回答的业务问题，须包含口径 |
| 关键指标 | 数组；每项含 metric_name、metric_value、metric_unit、metric_period |
| 证据列表 | 数组；每项含 source_type、source_name、evidence_text、related_metric、confidence |
| 归因结论 | 自然语言说明主要原因与影响范围 |
| 待补充数据 | 列出仍缺失的数据项 |
| 下一步建议 | **至少 2 条** |

**FR-6.2** 关键指标必须**可核验**：给定指标记录中的来源与口径，能复现同一数值。

**FR-6.3** 证据列表中的每一项必须可追溯到一次具体的工具调用或其返回。**不得**存在无来源证据。

**FR-6.4** 归因结论中提及的每个原因，必须在证据列表中存在对应条目。**不得**出现无证据支撑的原因。

**FR-6.5** 置信度必须由可解释规则产生（如样本量、覆盖周期、是否存在反驳性证据），**不得**由模型随意断言。

**FR-6.6** 多轮追问时，新一轮结果必须能引用前序轮次的结论与证据，允许修正前序结论，且必须记录修正原因。

**FR-6.7** 结果必须落库，并支持按任务查询历史结果。

### 5.7 上下文摘要（S7）

**FR-7.1** 当会话消息达到阈值时，系统必须生成上下文摘要，记录被压缩的原始消息区间（起止顺序号）。

**FR-7.2** 摘要必须保留：已确认的口径、已排除的假设、已发现的数据缺口、用户明确约束。**不得**丢失这些内容。

**FR-7.3** 摘要不得替代原始消息。原始消息必须仍可查询。

**FR-7.4** 后续分析任务使用摘要时，必须能追溯到被压缩的原始消息区间。

### 5.8 配置热更新（S8）

**FR-8.1** 系统必须提供配置读取与热更新能力，管理员可触发。

**FR-8.2** 热更新后，新配置必须对**之后**发起的请求生效，且无需重启进程。

**FR-8.3** 热更新必须记录：变更人、时间、变更前后的键值。**不得**静默覆盖。

**FR-8.4** 配置项必须有默认值。缺失配置项时，系统必须使用默认值并在日志中提示，**不得**启动失败或静默使用未定义行为。

### 5.9 运行日志（S9）

**FR-9.1** 系统必须记录每个分析任务的：启动、步骤推进、工具调用、错误、结束。

**FR-9.2** 日志必须可按任务、会话、级别查询。

**FR-9.3** 日志**不得**包含凭据明文或未脱敏的个人信息。

**FR-9.4** 分析任务失败时，日志必须包含可归因信息：失败步骤、工具名、错误类型。**不得**只记录"失败"。

### 5.10 结果导出与文件管理（S10）

**FR-10.1** 分析结果必须支持导出为文件，并支持重新下载。

**FR-10.2** 附件、导出结果、临时文件必须按原文 2.1.8 分目录存储：

| 类别 | 目录 |
| --- | --- |
| 附件 | `uploads/{user_id}/{conversation_id}/` |
| 导出 | `exports/{user_id}/{conversation_id}/` |
| 临时中间文件 | `workspace/{user_id}/{conversation_id}/` |

**FR-10.3** 删除会话时，必须同时删除上述三个目录。**不得**残留。

**FR-10.4** 下载与删除必须校验归属，跨用户访问必须被拒绝。

### 5.11 示例数据与演示（S11）

**FR-11.1** 必须提供以下六类业务场景的数据表与示例数据（原文 2.1.12）：

| 场景 | 最少需要的表 |
| --- | --- |
| 商品目录优化 | 商品表、类目表、搜索曝光表、点击表、转化表 |
| 客户行为分析 | 用户表、访问事件表、加购事件表、下单事件表 |
| 库存异常分析 | 库存表、入库表、出库表、销量表 |
| 评论反馈分析 | 评论表、评分表、商品表、退款表 |
| 市场表现分析 | 渠道表、投放表、订单表、销售汇总表 |
| 退款模式分析 | 退款申请表、退款原因表、订单表、用户表 |

**FR-11.2** 必须至少完成**两个**场景的完整演示链路，覆盖：登录 → 建会话 → 提问 → 澄清 → 取证 → 结果 → 追问 → 导出。

**FR-11.3** 示例数据必须自洽：跨表可关联，指标可算出，且存在可被发现的真实异常（供归因演示）。**不得**使用随机噪声填充导致无结论可出。

**FR-11.4** 示例数据必须包含足以支撑多个假设的维度（如流量、转化、客单价、品类结构、竞品价格、促销、库存、评分、退款），使因果类问题可被拆成多个可独立验证的假设。

**FR-11.5** 示例数据**不得**为了制造"假设被否定"的演示效果而人为埋入预设的假线索或反事实数据。假设成立与否必须由数据本身决定，不得预先设计。

> FR-11.4 与 FR-11.5 的区分：前者要求数据**维度足够**（否则 Agent 无料可查，AC-19 天然无法满足）；后者禁止**预设结论**（否则变成出题，不是分析）。

**FR-11.4** 必须提供数据库初始化脚本与接口说明文档。

## 6. 非功能需求

**NFR-1 可测性**：每条 FR 至少对应一个自动化测试，失败信息必须指明违反的编号。

**NFR-2 可观测性**：所有拒绝路径必须有计数器。计数器为 0 的拒绝路径视为未验证，不得声明可用。

**NFR-3 可重复**：演示链路必须可由单条命令重复执行且结果稳定。

**NFR-4 诚实的边界**：范围外能力描述必须与实际一致。以真实第三方系统名义描述本地实现，视为严重缺陷。

**NFR-5 无明文敏感信息**：日志、页面、错误响应不得出现凭据或未脱敏个人信息。

**NFR-6 只读业务数据**：分析任务对业务库的连接必须为只读，且该约束在绕过应用接口时同样生效。

**NFR-7 并发安全**：涉及唯一性与单次性的判定（同一会话单任务、长连接凭据一次性）必须在并发下成立，不得依赖"先查后写"。

**NFR-8 失败不静默**：任何工具失败、解析失败、超限终止，都必须产生可查询记录与计数。静默跳过视为缺陷。

## 1. 目的与读者

本文档定义本系统**对外可观察的行为**：什么输入、什么输出、什么状态下拒绝、拒绝时给出什么依据。

本文档**不**规定：编程语言、框架、数据库、表结构、目录组织、部署方式、算法选择。这些属于实现方案，见 `design-etl-agent-guardrail.md`。实现方案与本文档冲突时，以本文档为准。

读者：实现者、测试者、评审者（面试场景下的追问方）。

### 1.1 约定

需求语句使用以下限定词，具有规范效力：

| 词 | 含义 |
| --- | --- |
| **必须** | 绝对要求。不满足即为缺陷 |
| **不得** | 绝对禁止。出现即为缺陷 |
| **应当** | 强建议。偏离须在实现方案中写明理由 |
| **可以** | 可选 |

每条需求有唯一编号 `FR-*` / `NFR-*` / `AC-*`，编号一经分配不复用、不改义，废弃时标注 `[已废弃]`。

## 2. 术语（规范性）

以下术语在本文档中具有确定含义，不随实现变化。

| 术语 | 定义 |
| --- | --- |
| **制品（Artifact）** | 一次待执行的数据搬运方案的全部可执行描述：源、目标、字段映射、过滤与清洗规则、写入模式。制品一旦定版即不可修改 |
| **制品摘要** | 对制品内容计算的定长指纹。内容任一字节变化，摘要必然变化 |
| **版本（Version）** | 制品的一个不可变快照。同一 Pipeline 可以有多个版本，各自独立 |
| **元数据画像** | 对数据源只读探查的结果：表、字段、类型、主键、近似规模、脱敏样本。附带自身摘要 |
| **准备单（Preparation）** | 一次执行意图的冻结记录。含：制品摘要、元数据画像摘要、资源范围、影响范围、数据分级、运行预算、回滚方案。**产生准备单不得有任何外部副作用** |
| **指纹（Fingerprint）** | 由制品摘要、元数据画像摘要、资源范围、运行预算、执行器标识、环境标识共同推导的值。用于判断"要执行的东西是否仍是当初审批的东西" |
| **审批槽（Approval Slot）** | 一个独立、具名的审批职责。一个准备单需要哪些槽，由风险等级决定 |
| **四眼原则** | 提交者不得审批自己提交的准备单；同一人不得占用同一准备单的多个审批槽 |
| **能力凭证（Capability）** | 一次性的、短时的、限定范围的执行许可。携带被许可的工具、主体、环境、制品摘要与有效期 |
| **消费（Consume）** | 凭证被用于实际执行，此后永久失效 |
| **影子表** | 执行期写入的临时目标。对外不可见，发布前对外部读者不存在 |
| **发布（Publish）** | 把影子表变为正式目标的动作。必须原子完成 |
| **质量契约** | 对目标数据的字段级约束集合，以及不合规行的处置方式 |
| **错误行** | 未满足质量契约的记录。必须与有效数据分离，不得进入正式目标 |
| **运行预算** | 一次执行被允许消耗的上限：读取行数、写入字节、时长、输出放大比、错误拒绝率 |
| **监督** | 执行期对预算的持续比对。越线必须产生可观察事件 |
| **证据账本** | 只追加的关键事件记录。每条记录与其前一条存在密码学绑定，历史不可否认 |
| **审计可追溯** | 任一执行结果，都能从账本还原出"谁、在何时、基于哪份审批、执行了哪个制品" |

## 3. 范围

### 3.1 范围内

| 编号 | 能力域 | 简述 |
| --- | --- | --- |
| S1 | 身份与职责 | 用户、项目、角色槽、职责分离 |
| S2 | 数据源与探查 | 连接管理、只读元数据探查、脱敏样本 |
| S3 | 方案生成 | 自然语言需求 → 制品候选 |
| S4 | 门禁 | 确定性校验，含危险操作检测 |
| S5 | 版本化 | 制品定版与不可变性 |
| S6 | 准备 | 冻结执行意图与前序事实 |
| S7 | 审批 | 双槽审批与职责分离 |
| S8 | 授权 | 指纹复验、凭证签发、防重放 |
| S9 | 执行 | 受管执行、指标回传、副作用唯一出口 |
| S10 | 监督 | 预算监控与越线处置 |
| S11 | 质量与发布 | 质量分流、原子发布、回滚 |
| S12 | 审计 | 证据账本、链完整性校验 |

### 3.2 范围外（**明确不做，需在交付说明中声明**）

| 不做的事 | 原因 |
| --- | --- |
| 真实大数据引擎集群集成 | 本系统的考点是执行治理，不是数据搬运性能。执行器以可替换插槽形式存在 |
| 多租户与计费 | 与考点无关 |
| 模型效果评测平台 | 生成质量不是本系统的验收对象 |
| 生成策略的自动进化闭环 | 需要长期数据积累，本项目周期内无法形成可信结论 |
| 生产级高可用与容灾 | 单实例可运行即可，不做集群 |
| 执行器内部算法优化 | 执行器只要求语义正确、可观测、可中断 |

> **纪律**：范围外的能力，**不得**在交付说明、演示、简历中以"已实现"或"已集成"措辞描述。凡未做即写"未做"。

## 4. 相关方与角色

| 角色 | 职责 | 不得做的事 |
| --- | --- | --- |
| 申请人 Maker | 登记数据源、发起探查、输入需求、生成与调试制品、提交审批 | 不得审批自己提交的准备单 |
| 数据审批人 Checker-Data | 审查需求与制品的语义一致性、字段映射、脱敏前后的结构差异、质量规则 | 不得在无准备单时审批；不得审批自己提交的 |
| 安全审批人 Checker-Security | 审查资源范围、数据分级、预算合理性、回滚方案可行性 | 同上；且不得与数据审批人为同一人（同一准备单内） |
| 操作员 Operator | 在审批齐备后触发提交与执行、监控、取消、回滚 | 不得在审批未齐备时触发执行 |
| 审计员 Auditor | 查看事件、校验账本完整性、查看质量报告 | 不得修改任何业务数据 |

## 5. 功能需求

### 5.1 身份与职责（S1）

**FR-1.1** 系统必须区分身份（谁）与职责（在本项目里能做什么）。职责在项目范围内授予，不得跨项目继承。

**FR-1.2** 系统必须支持五种角色：申请人、数据审批人、安全审批人、操作员、审计员。一个用户可以在不同项目持有不同角色。

**FR-1.3** 对任一受保护操作，系统必须输出允许或拒绝的明确结论。拒绝时必须给出可读依据（缺哪个角色、缺哪个前提），不得只返回泛化错误。

### 5.2 数据源与探查（S2）

**FR-2.1** 系统必须支持登记数据源连接，并支持独立的连通性测试动作。测试结果必须区分"配置错误"与"网络不可达"两类失败。

**FR-2.2** 元数据探查必须为只读。任何探查动作不得改变数据源中的数据或结构。

**FR-2.3** 探查结果必须包含：表清单、字段清单、字段类型、主键、近似规模、样本。样本中出现的邮箱、手机号、身份证号、银行卡号必须脱敏后返回。

**FR-2.4** 探查结果必须计算自身摘要。该摘要参与后续指纹推导（见 FR-8.2）。**源结构变化必须导致摘要变化**。

**FR-2.5** 凭据必须密文保存。任何接口响应、日志、页面**不得**回显凭据明文。

### 5.3 方案生成（S3）

**FR-3.1** 系统必须接受自然语言需求，产出结构化的制品候选。

**FR-3.2** 生成的候选**必须**经过门禁（S4）校验才可定版。**不得**存在跳过门禁直接定版的路径。

**FR-3.3** 当需求缺少必要信息（源、目标、关键字段映射、过滤条件）时，系统必须提出澄清并要求补充，**不得**以默认值静默填充后继续。

**FR-3.4** 澄清过程中断后，系统必须在重启后从断点继续，**不得**要求重新输入已提供的信息。

**FR-3.5** 生成来源（模型生成 / 规则模板生成）必须可识别并记录在制品元数据中。

### 5.4 门禁（S4）

**FR-4.1** 门禁必须由确定性逻辑构成：同一输入必须恒得同一结论。**不得**由模型判断通过与否。

**FR-4.2** 门禁必须至少覆盖：语法有效性、字段存在性、类型兼容性、主键冲突、写入模式与目标的匹配性。

**FR-4.3** 门禁必须识别以下危险操作并拒绝（P0）：

| 危险操作 | 说明 |
| --- | --- |
| 删除或清空目标 | 结构或数据被移除 |
| 无过滤条件的全量覆盖写 | 缺少可验证的写入边界 |
| 写入系统表或元数据表 | 越出业务数据边界 |
| 读写未在本准备单资源范围内声明的对象 | 范围外访问 |
| 跨项目访问对象 | 越权 |
| 直接读写影子表 | 绕过发布协议 |

**FR-4.4** 门禁必须输出结构化结论：通过 / 带告警通过 / 拒绝，以及每条命中的规则编号与命中位置。

**FR-4.5** 拒绝结论必须可复现：同一制品重复校验得到同一结论。

### 5.5 版本化（S5）

**FR-5.1** 定版后的制品**不得**被修改。任何修改必须产生新版本。

**FR-5.2** 每个版本必须携带摘要，摘要由制品内容确定。

**FR-5.3** 系统必须能列举同一 Pipeline 的所有历史版本，并比较任意两版本的差异。

**FR-5.4** 对已定版版本的修改尝试，必须被拒绝并记录事件。**不得**静默忽略。

### 5.6 准备（S6）

**FR-6.1** 生成准备单**不得**产生任何外部副作用。此约束必须可被测试验证。

**FR-6.2** 准备单必须冻结：制品摘要、元数据画像摘要、资源范围（允许读写的对象清单）、影响范围（预计写入量级与受影响对象）、数据分级、运行预算、回滚方案、推导出的指纹。

**FR-6.3** 准备单一旦生成，其冻结字段**不得**被修改。需要变更时必须作废并要求重新准备。

**FR-6.4** 系统必须根据风险特征为准备单指派所需审批槽。风险分级与所需槽位的对应关系必须显式、可查、可测。

**FR-6.5** 同一 Pipeline 同一时间**不得**存在多个处于"待审批"或之后状态的准备单。

### 5.7 审批（S7）

**FR-7.1** 每个审批槽必须由具名用户独立决策。决策必须记录决策人、时间、结论、意见。

**FR-7.2** 提交者**不得**审批自己提交的准备单。此禁止**必须由存储层强制**，使绕过应用接口的写入同样被拒绝。

**FR-7.3** 同一人**不得**在同一准备单内占用多个审批槽。此禁止**必须由存储层强制**。

**FR-7.4** 任一槽位拒绝，准备单即终止，**不得**进入提交阶段。已完成的其它槽位决策保留为记录。

**FR-7.5** 每个审批槽**不得**被决策多次。

**FR-7.6** 审批人看到的必须是冻结后的事实。**不得**展示可能已变化的活动数据。

### 5.8 授权（S8）

**FR-8.1** 提交前，系统**必须**重新计算指纹，并与准备单冻结的指纹逐项比对。任一不符即拒绝提交。

**FR-8.2** 指纹必须覆盖：制品摘要、元数据画像摘要、资源范围、运行预算、执行器标识、环境标识。**任一项变化都必须导致指纹变化**。

**FR-8.3** 指纹比对、凭证签发、执行任务的建立，**必须**构成一个不可分割的整体：三者要么全部发生，要么全部不发生。**不得**出现"凭证已签发但无对应执行"或"执行已建立但无有效凭证"的中间态。

**FR-8.4** 凭证必须绑定：被许可的工具、主体、环境、制品摘要、有效期。任一不符即拒绝。

**FR-8.5** 凭证有效期**不得超过** 5 分钟。

**FR-8.6** 凭证**必须且只能**被消费一次。重复消费必须被拒绝。

**FR-8.7** 重复消费的拒绝**必须在并发条件下成立**：同一凭证的 N 个并发消费请求中，必须恰好 1 个成功、N−1 个被拒绝。**不得**出现"先查询再写入"式的判定。

**FR-8.8** 未通过 FR-8.1 校验时，**不得**签发凭证。

### 5.9 执行（S9）

**FR-9.1** 所有产生外部副作用的操作，**必须**经过唯一出口。**不存在**第二条写入数据的路径。

**FR-9.2** 无有效凭证的执行请求必须被拒绝，并记录事件。

**FR-9.3** 执行任务的建立与投递**必须**保证：业务事实落库成功而投递丢失的情况不得发生；投递成功而业务事实回滚的情况不得发生。

**FR-9.4** 执行请求**必须**幂等：同一执行请求被重复投递时，实际副作用**不得**重复发生。

**FR-9.5** 投递失败必须重试，重试次数达上限后进入"待人工处置"，并计数上报。**不得**静默丢弃。

**FR-9.6** 执行必须向调用方回传：输入记录数、输出记录数、错误记录数、处理字节数、开始与结束时间、最终状态。

**FR-9.7** 执行状态至少包含：待执行、已认领、运行中、成功、失败、被终止、已取消、已回滚。状态迁移必须单向、可审计。

**FR-9.8** 系统必须支持取消运行中的执行；取消后已产生的副作用必须可识别、可回滚。

### 5.10 监督（S10）

**FR-10.1** 执行期必须持续比对运行预算，至少覆盖：读取行数、写入字节、执行时长、输出放大比、错误拒绝率。

**FR-10.2** 越线必须产生可观察事件，并至少区分两个级别：预警（告警但继续）、越限（终止）。

**FR-10.3** 越限终止必须留下快照：越线指标、当时的进度、采取的动作。

**FR-10.4** 预算的取值**必须**来自准备单冻结值，**不得**在执行期被修改。

### 5.11 质量与发布（S11）

**FR-11.1** 执行必须写入影子目标。发布前，正式目标对任何外部读者**不得**呈现新数据。

**FR-11.2** 未满足质量契约的记录**必须**与有效数据分离，并记录：源记录位置、违规规则编号、原始值。

**FR-11.3** 错误行**不得**进入正式目标。

**FR-11.4** 发布必须原子完成：任何时刻读取正式目标，只能看到完整的旧数据或完整的新数据，**不得**看到混合状态。

**FR-11.5** 拒绝率超过预算时，**不得**发布，执行必须终止并进入失败或已回滚状态。

**FR-11.6** 系统必须支持受管回滚：撤销影子目标、将执行标记为已回滚、写入账本。回滚**不得**影响正式目标。

### 5.12 审计（S12）

**FR-12.1** 系统必须记录至少以下事件：登录、连接创建与修改、探查、生成、门禁结论、定版、准备、审批决策、提交、凭证签发、凭证消费、执行状态迁移、监督越线、发布、回滚、账本校验。

**FR-12.2** 账本必须只追加。任何修改或删除历史事件的操作**必须**被拒绝。

**FR-12.3** 每条事件必须与其前一条存在密码学绑定，使得修改任一历史事件导致其后全部校验失败。

**FR-12.4** 系统必须提供链完整性校验动作，输出：通过 / 失败（定位到首个不一致事件）。

**FR-12.5** 校验必须能识别"整链重算"式篡改，即不仅校验链内一致性，还需对周期性锚点做独立校验。

**FR-12.6** 任一执行结果必须可追溯：给定执行标识，能还原提交人、审批人、审批时间、制品版本、摘要、执行时间、指标、监督事件。

## 6. 非功能需求

**NFR-1 可测性**：每条 FR 必须至少对应一个自动化测试。测试失败信息必须指明违反了哪个编号。

**NFR-2 可观测性**：所有拒绝必须有计数器。计数器为 0 的拒绝路径视为未验证，不得声明可用。

**NFR-3 可重复**：端到端演示必须可由单条命令重复执行，且结果稳定。

**NFR-4 诚实的边界**：范围外能力（§3.2）在交付说明中的描述必须与实际一致。以真实引擎或框架的名义描述模拟实现，视为严重缺陷。

**NFR-5 无明文敏感信息**：日志、页面、错误响应中不得出现凭据或未脱敏的个人信息。

**NFR-6 存储层强制**：凡标注"必须由存储层强制"的约束（FR-7.2、FR-7.3、FR-5.1、FR-12.2），必须在绕过应用接口直接写入时同样生效。

**NFR-7 并发安全**：涉及唯一性、单次性的判定（FR-8.6、FR-8.7、FR-5.6.5、FR-7.5），必须在并发请求下成立。

## 7. 交收标准（AC）

本节定义"做完"的判据。每条 AC 对应一组 FR。

| 编号 | 判据 | 对应 |
| --- | --- | --- |
| AC-1 | 五个角色可分别登录，权限矩阵（5 角色 × 全部受保护接口）全部符合预期，含越权拒绝 | FR-1.* |
| AC-2 | 能登记并测试连接；探查只读；样本脱敏；源结构变化后摘要随之变化 | FR-2.* |
| AC-3 | 自然语言需求能产出候选；缺信息时提出澄清；中断重启后可续 | FR-3.* |
| AC-4 | 六类危险操作全部被门禁拒绝，且结论可复现、含规则编号 | FR-4.* |
| AC-5 | 已定版版本无法修改（含绕过接口的直接写入尝试），修改尝试有事件记录 | FR-5.*、NFR-6 |
| AC-6 | 生成准备单后，数据源与目标状态零变化（可验证）；冻结字段不可改 | FR-6.* |
| AC-7 | 自批被拒；同一准备单内一人占双槽被拒；两者在绕过接口直写时同样被拒 | FR-7.2、FR-7.3、NFR-6、NFR-7 |
| AC-8 | 提交前替换制品版本，提交被拒绝并说明原因 | FR-8.1、FR-8.2 |
| AC-9 | 凭证并发消费 N 次，恰好 1 次成功；过期凭证被拒；绑定项不符被拒 | FR-8.4~8.7、NFR-7 |
| AC-10 | 提交后、执行前强杀进程，重启后执行仍发生且仅发生一次 | FR-9.3、FR-9.4 |
| AC-11 | 构造超预算输入，执行被终止，正式目标保持原状，快照可查 | FR-10.*、FR-11.5 |
| AC-12 | 含错误行的输入：错误行在错误记录中且不打入正式目标；发布前查正式目标仍是旧数据 | FR-11.1~11.4 |
| AC-13 | 篡改任一历史事件后，链校验失败并定位到该事件；整链重算同样被判失败 | FR-12.3~12.5 |
| AC-14 | 给定执行标识可还原完整追溯链（从提交人到发布） | FR-12.6 |
| AC-15 | 端到端演示可单命令重复执行，含一条成功链路与一条越限回滚链路 | NFR-3 |
